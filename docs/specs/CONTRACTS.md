# SPEC: Contracts Catalog

Status: §3 Approved (owner, 2026-10-19, Q-CT-11); §4–§8 Draft, approved piece by piece as each handler lands (Q-CT-6) · Owner: — · Tracker: NX-021, NX-101, NX-170, NX-190, NX-253 · Related ADRs: 0002, 0004 · Related specs: WIRE-PROTOCOL, GAMEPLAY, FOG-OF-WAR, CHAT-GATEWAY, OPS-ADMIN, IDENTITY

> All numeric limits in this spec (lengths, rates, sizes) are **PROPOSED** (DATA-INTEGRITY DI-7) unless they quote another spec. Behavior that depends on an open owner decision cites its Q-ID.

## 1. Purpose
This is the single catalog of every typed message that crosses a module or process boundary: chat input, commands, sim events, server↔overlay wire messages, and the internal admin API. `/contracts` (JSON Schema) is the source of truth. Generated Pydantic and TypeScript types are derived from it, and hand-written wire types are forbidden (AGENTS.md rule 6).

## 2. Goals / Non-goals
- **Goals:**
  - One schema per message.
  - Generated types.
  - Explicit validation rules.
  - A defined FoW redaction rule for every event.
  - Explicit versioning.
- **Non-goals:**
  - Database table layout (DATA-MODEL spec).
  - Balance values (balance config).
  - Platform-native payloads (CHAT-GATEWAY adapters own those).

## 3. Conventions

### 3.1 Files and tooling
```
contracts/
  common/     enums.json, ids.json, geometry.json, text.json, envelope.json
  commands/   command.json (discriminated union), <kind>.json per command
  events/     event.json (discriminated union), <kind>.json per event
  wire/       hello.json, welcome.json, snapshot.json, delta.json, hud.json, audio.json, control.json, ack.json
  admin/      requests/*.json, responses/*.json, audit.json
  VERSION     PROTOCOL_VERSION as "MAJOR.MINOR"
```
- **Schemas:**
  - JSON Schema draft 2020-12.
  - Every object sets `additionalProperties: false` when *produced*. Consumers tolerate unknown fields (WP-2).
  - Unions are discriminated by a `kind` (commands, events) or `type` (wire) const field.
- **Generated types:** Python (Pydantic v2 via datamodel-code-generator; shared `$defs` become type aliases) goes to `services/sim/src/nexus/contracts/gen/` for every schema, so the hand-written `nexus.contracts` package docstring survives regeneration. TS (json-schema-to-typescript) goes to `apps/overlay/src/contracts/` for the wire messages and the event union, which is what the overlay consumes. Commands and events carry their header and payload fields flat in one object. Both outputs are committed; how to change a contract: `contracts/README.md`. `make contracts` regenerates both; the CI `contracts` job runs it and fails on any diff (NX-021, Q-CT-10).
- **Use in the kernel (Q-CT-7):** `nexus.core` may import the generated `nexus.contracts`. Events are built on the hot path with Pydantic's `model_construct` (no re-validation); full validation happens at the boundaries (gateway in, wire out) and in tests.
- **Scope (Q-CT-6):** a schema is added in the same PR as the code that produces or handles it (AGENTS.md rule 6a). NX-021 adds only the seed set: `common/` ids and enums, `ChatEnvelope`, command `JOIN`, event `UnitSpawned`, and wire `Hello`, `Welcome`, `Snapshot`.
- **Naming:**
  - Schema titles are `PascalCase`.
  - Fields are `snake_case` on the wire, in both Python and TS. TS does not camelCase, to avoid a mapping layer.
  - Enum values are `UPPER_SNAKE`.

### 3.5 Text fields
Every user-derived string uses `common/text.json#SafeText`. That means:
- NFKC-normalized
- control, bidi and zero-width characters stripped
- a `maxLength` stated per field

Text shown on stream additionally requires `ModeratedText`, a SafeText already approved by moderation (SEC-MOD-1). Its schema has a `moderation_ref` field carrying the approval id. Raw display names never appear in sim, wire, or event schemas (Q-MOD-1). Only `Callsign` values do.

### 3.6 Versioning
- `PROTOCOL_VERSION = MAJOR.MINOR` lives in `contracts/VERSION`, starting at `0.1` (Q-CT-8). While it is 0.x, every change bumps MINOR and the compat check only reports; MAJOR enforcement starts at `1.0`, the first public build.
- **MINOR bump** for additive changes: a new optional field, a new event or message kind, or a new enum value in a field whose consumers must tolerate unknowns.
- **MAJOR bump** for anything else: removing or renaming a field, a type change, required-ness added, semantics changed, or a new enum value in a closed enum.
- CI compat check (NX-021, Q-CT-8, Q-CT-9): a small tested script in `scripts/` diffs the schemas against the PR's base branch and flags removed properties, newly required fields, changed types and removed enum values. From `1.0`, a breaking change without a MAJOR bump fails.
- Command-log and snapshot files record the `PROTOCOL_VERSION` they were written with. A replay across a MAJOR change requires a migration or must be refused (SIM-CORE §6).

### 5.2 Catalog
Wire shapes only: which chat commands exist, their syntax, rank and phase are in [COMMAND-CATALOG](COMMAND-CATALOG.md) (Q-CMD-1). "Who" refers to `source`. **While paused (Q-ALN-2, SIM-CORE SC-11):** commands that do not change the world still work: `ME` (and its alias `!status`), `QUIET`, the info commands, `SET_CALLSIGN`, and a `JOIN` from a commander with no live unit, which always joins the reserve queue, even when a slot is free (it never spawns while paused, Q-ALN-26), and spawns FIFO after resume. **Staff and system commands while paused (Q-ALN-24):** the safety actions always apply: `STAFF_BAN`, `FORGET` (its unit despawn included), `STAFF_KILL_SWITCH`, `STAFF_CAMPAIGN_PAUSE` (which rejects `ALREADY_PAUSED`), `STAFF_CAMPAIGN_RESUME` and `STAFF_CAMPAIGN_END`. `STAFF_CONFIG_RELOAD` is validated and held, then applied in the tick the campaign resumes (`BalanceReloaded` is emitted then). `STAFF_DIRECTOR_OVERRIDE` is rejected with `CAMPAIGN_PAUSED`. `STAFF_UNBAN`, `STAFF_PURGE_UNITS` (its unit despawn included) and `SYS_SET_CALLSIGN` apply as when running (Q-ALN-36). `ADVISOR_CHOICE` and the GM commands (`STAFF_GM_TAKEOVER`, `STAFF_GM_OPERATION`, `STAFF_GM_VERDICT`, `STAFF_GM_LIMITS`, `STAFF_GM_INJECT_JOB`) are rejected with `CAMPAIGN_PAUSED`; `STAFF_GM_RELEASE` applies, whether from the GM or from SYSTEM on auto-release (Q-ALN-36).

Their syntax and rank are in COMMAND-CATALOG §3 and design notes in GAMEPLAY-LATER §3; payloads and rejects are written here in the PR that adds the handler.

### 5.3 RejectReason enum
Every value listed in the §5.2 table (rejects named only for reserved commands join the enum with their handler), plus `CAMPAIGN_PAUSED` (a world-changing chat command, a `STAFF_DIRECTOR_OVERRIDE`, an `ADVISOR_CHOICE` or a GM command other than `STAFF_GM_RELEASE`, while paused; Q-ALN-2, Q-ALN-24, Q-ALN-36), `INVALID_PAYLOAD`, `BANNED`, and `INTERNAL_ERROR` (SC-7: the kernel converts an unexpected validation failure into this event instead of raising; SC-8: also the reason for a command dropped on crash recovery). Every reject is emitted as `CommandRejected` (§6). Chat replies are aggregated into digests and never sent per reject (CHAT-GATEWAY §6). The schema enum holds only the values code emits (`contracts/README.md`); today that is `INTERNAL_ERROR` (NX-102) and, from the JOIN handler (NX-122), `ROLE_UNKNOWN`, `UNIT_IN_SORTIE`, `RESPAWN_COOLDOWN`, `NODE_UNKNOWN`, `NODE_INVALID_FOR_UNIT`, `FOLLOW_TARGET_INVALID` (every follow target until follow lands, Q-GP-31), `CAMPAIGN_PAUSED`, `INVALID_PAYLOAD` and `RESERVE_QUEUE_FULL`. `QUEUED_RESERVE` is never emitted: a queued JOIN emits `ReserveQueueJoined`, not a reject.

## 6. Sim event catalog
`events/event.json` is a discriminated union on `kind`.
- **Common fields:** `kind`, `tick`, `event_seq` (int, campaign-wide, monotonically increasing and deterministic, SIM-CORE SC-14; a crash-recovery replay assigns the same values), `campaign_id`.
- **Consumers:** **B** broadcast/overlay, **P** progression, **A** audio/sitrep, **C** clips scoring, **O** ops metrics/logs, **R** replay (all events are replayable; R is implied).
- **Redaction:** the rule says what the *public coalition view* receives (FOW-1, FOW-3) **during the live campaign**. Internal consumers (P, A, C, O) get the full event. Anything A or C outputs during the campaign is built only from redacted fields. Once `CampaignEnded` is emitted, archives, replays and recaps (including "what you didn't see") are exempt from FOW-1 and may use the full events (Q-ALN-21).

The kernel derives the counts from applied commands, so they are deterministic.

**Who decides an entity is hidden:** the redaction pass uses the coalition visibility predicate (currently tracked) in the latest computed view as of the event's tick (FOW-1, FOW-5); an entity in the last-known set may appear only in `LastKnownView`, and a discovered facility only through its marker fields (`NodeView.facilities`, FOW-13). Property test: no public payload references an `EntityId` that fails the predicate.

Field shapes:
- `EntityView`:
  - `{entity_id, unit_kind, side, domain, owner_kind, callsign|null, pos:{x_m:int,y_m:int}, heading_deg:int, speed_mps:int, hp_pct:int 0–100, damage_state: DamageState, painted: bool, spotted: bool|null (own units only, null for the other side; FOW-12), package_id|null, follow_entity_id|null, follower_count:int, cosmetic:{halo|null, trail|null}, badges: string[] ≤ 4, probation: bool, auto: bool}`
  - `probation` is true only while the operator has an active conduct restriction (Q-MOD-6); no score is ever sent. Always false for AI entities.
  - `auto` is true while a commander's unit is AI-run after idle handoff; the overlay shows the AUTO tag (Q-GD-35, Q-ALN-9). Always false for AI-owned entities, which use the `[AI]` label instead.
  - Only tracked entities appear; blobs and last-known tracks are separate lists. `callsign` is null for AI entities, which render an `[AI]` label (DI-5).
- `EntityPatch`: `entity_id` plus only the changed fields of `EntityView`.
- `NodeView`: `{node_id, owner: NodeOwner, capture:{side|null, progress_pct:int}, stock_pct:int|null, starvation: OK|LOW|EMPTY|null, hp_pct:int|null, facilities: [{entity_id, kind: UnitKind, variant, pos, ring_m: int|null, state: DamageState|null, emitting: bool|null, confirmed_tick: int|null}]}` (null for own facilities). `stock_pct`, `starvation` and `hp_pct` are null for ENEMY nodes the coalition can't see (DI-1). `facilities` lists only the viewer side's own facilities and enemy facilities it has discovered (FOW-13, Q-FOW-15). For a discovered enemy facility, `state` and `emitting` are the last confirmed values as of `confirmed_tick`; they change only when the side observes the site again.
- `BlobView`: `{blob_id: BlobId, cell_center:{x_m,y_m}, size: S|M|L}`.
- `LastKnownView` (FOW-6a, Q-FOW-1): `{entity_id, unit_kind, pos:{x_m,y_m}, heading_deg:int, seen_tick}`. Only for entities the viewer's side tracked before; dropped after `fow.track_fade_s`.
- `TickerItem`: `{tick, text: ModeratedText ≤ 100, category: CAPTURE|SUPPLY|COMBAT|DIRECTOR|SYSTEM}`.
- `Panels`:
  - `campaign_status: {nodes_held:{coalition,enemy,neutral}, result|null}` (the operator breakdown comes from `Hud.operators`)
  - `tasking_needed: [{job_kind, node_id|null, sector_id|null, slots_open}] ≤ 3` (GAMEPLAY §1b)
  - `top_commanders: {role, rows:[{callsign, value}] ≤ 5}[]`. Real rows only; never padded (DI-4).
  - `active_packages: [{name, lead_callsign|null, member_count}] ≤ 6`: **P4**, ships with packages (Q-ALN-18).
  - Top Commanders is in the default panel rotation (Q-ALN-18). The former `latest_major_event` panel field is removed: the latest major event is an overlay interrupt toast, not a panel (Q-ALN-18, OVERLAY).

## 8. Internal HTTP / admin API
- **Two apps (Q-ARCH-7):** this API backs the private **Command Center** only. The **public site** (replays, leaderboards, stats, later player login) is a separate app with its own read-only API and **no admin routes**; they share contracts and a design system, not an API, so a public-site bug can't reach admin powers.
- **Binding:** served by `nexus.ops` on localhost or the tailnet only, plus the Discord `AdminChannel` (ADMIN-RBAC §7.1). Never exposed publicly; a DAST pass is required before any public exposure (Q-RB-4).
- **Auth:**
  - Every `/admin/*` route requires an authenticated staff session and is authorized per route against the RBAC matrix (ADMIN-RBAC §4). Passkeys (WebAuthn) for owner and admins; Discord OAuth for moderators later, via a verified link (Q-ARCH-12). In P2 there is a single staff member, the OWNER (ADMIN-RBAC §10).
  - Session cookie is `Secure; HttpOnly; SameSite=Strict`, plus a CSRF token on POST (SEC-ID-5 pattern).
  - `/health` and `/metrics` need no auth but are tailnet- or localhost-bound.
- **Responses:** all are JSON, with schemas in `contracts/admin/`.

## 9. Failure modes
| Failure | Behavior |
|---|---|
| Producer emits a payload that fails its schema | The bug is caught in tests. At runtime the producer logs `contract_violation` with the schema id and drops the message (no partial send). Metric + alert. |
| Consumer receives an unknown field or type | Ignore and log (WP-2). Never crash. |
| PROTOCOL_VERSION major mismatch on `Hello` | Server replies `Control{action: RELOAD}`. The overlay shows "UPDATE REQUIRED" (WP-1). |
| Replay log from an older MAJOR | Replay CLI refuses unless a registered migration exists. |
