# SPEC: Contracts Catalog

Status: Draft · Owner: — · Tracker: NX-021, NX-101, NX-170, NX-190, NX-253 · Related ADRs: 0002, 0004 · Related specs: WIRE-PROTOCOL, GAMEPLAY, FOG-OF-WAR, CHAT-GATEWAY, OPS-ADMIN, IDENTITY

> All numeric limits in this spec (lengths, rates, sizes) are **PROPOSED** (DATA-INTEGRITY DI-7) unless they quote another spec. Behavior that depends on an open owner decision cites its Q-ID.

## 1. Purpose
This is the single catalog of every typed message that crosses a module or process boundary: chat input, commands, sim events, server↔overlay wire messages, and the internal admin API. `/contracts` (JSON Schema) is the source of truth. Generated Pydantic and TypeScript types are derived from it, and hand-written wire types are forbidden (AGENTS.md rule 6).

## 2. Goals / Non-goals
- **Goals:**
  - One schema per message.
  - Generated types.
  - Explicit validation rules.
  - A defined FoW redaction rule for every event.
  - Explicit versioning.
- **Non-goals:**
  - Database table layout (DATA-MODEL spec).
  - Balance values (balance config).
  - Platform-native payloads (CHAT-GATEWAY adapters own those).

## 3. Conventions

### 3.1 Files and tooling
```
contracts/
  common/     enums.json, ids.json, geometry.json, text.json, envelope.json
  commands/   command.json (discriminated union), <kind>.json per command
  events/     event.json (discriminated union), <kind>.json per event
  wire/       hello.json, welcome.json, snapshot.json, delta.json, hud.json, audio.json, control.json, ack.json
  admin/      requests/*.json, responses/*.json, audit.json
  VERSION     PROTOCOL_VERSION as "MAJOR.MINOR"
```
- **Schemas:**
  - JSON Schema draft 2020-12.
  - Every object sets `additionalProperties: false` when *produced*. Consumers tolerate unknown fields (WP-2).
  - Unions are discriminated by a `kind` (commands, events) or `type` (wire) const field.
- **Generated types:** Python (Pydantic v2 via datamodel-code-generator) goes to `services/sim/nexus/contracts/`, and TS (json-schema-to-typescript) goes to `apps/overlay/src/contracts/`. Both are committed. CI regenerates them and fails on any diff (NX-021).
- **Naming:**
  - Schema titles are `PascalCase`.
  - Fields are `snake_case` on the wire, in both Python and TS. TS does not camelCase, to avoid a mapping layer.
  - Enum values are `UPPER_SNAKE`.

### 3.4 Units of measure
| Quantity | Unit |
|---|---|
| Distance | metres |
| Speed | m/s |
| Time | ticks; wall-clock only in envelopes and admin audit (RFC 3339 UTC) |
| Angle | degrees, 0 = north, clockwise |
| Supply and cargo | integer stock units |
| HP | integer |
| Fuel | integer per-mille (0–1000) |

Each field states its unit in its schema `description`. Wire positions are quantized to 1 m (WP-4).

### 3.5 Text fields
Every user-derived string uses `common/text.json#SafeText`. That means:
- NFKC-normalized
- control, bidi and zero-width characters stripped
- a `maxLength` stated per field

Text shown on stream additionally requires `ModeratedText`, a SafeText already approved by moderation (SEC-MOD-1). Its schema has a `moderation_ref` field carrying the approval id. Raw display names never appear in sim, wire, or event schemas (Q-MOD-1). Only `Callsign` values do.

### 3.6 Versioning
- `PROTOCOL_VERSION = MAJOR.MINOR` lives in `contracts/VERSION`.
- **MINOR bump** for additive changes: a new optional field, a new event or message kind, or a new enum value in a field whose consumers must tolerate unknowns.
- **MAJOR bump** for anything else: removing or renaming a field, a type change, required-ness added, semantics changed, or a new enum value in a closed enum.
- CI compat check (NX-021): diff schemas against `main`. A breaking change without a MAJOR bump fails.
- Command-log and snapshot files record the `PROTOCOL_VERSION` they were written with. A replay across a MAJOR change requires a migration or must be refused (SIM-CORE §6).

### 5.3 RejectReason enum
Every value listed in §5.2, plus `INVALID_PAYLOAD`, `BANNED`, `LATE` (applied, but flagged — SC-6), and `INTERNAL_ERROR` (SC-7: the kernel converts an unexpected validation failure into this event instead of raising). Every reject is emitted as `CommandRejected` (§6). Chat replies are aggregated into digests and never sent per reject (CHAT-GATEWAY §6).

## 6. Sim event catalog
`events/event.json` is a discriminated union on `kind`.
- **Common fields:** `kind`, `tick`, `event_seq` (int, per tick, deterministic order), `campaign_id`.
- **Consumers:** **B** broadcast/overlay, **P** progression, **A** audio/sitrep, **C** clips scoring, **O** ops metrics/logs, **R** replay (all events are replayable; R is implied).
- **Redaction:** the rule says what the *public coalition view* receives (FOW-1, FOW-3). Internal consumers (P, A, C, O) get the full event. Anything A or C outputs is built only from redacted fields.

| `StateHash` | `tick`, `hash: hex` | not public | O R |

**PresenceSnapshot** is emitted every `presence.emit_every_ticks` (CONFIG-AND-CONTENT §6.6) over the trailing `presence.window_s`. Both counts include only `COMMANDER` owners (DI-5): `active_humans` = commanders with a live unit or an accepted command in the window (drives the HUD "Operators active" count and its breakdown, Q-CT-4; it does **not** pause the clock, Q-GD-4 amended / Q-SM-5); `distinct_humans_active` = distinct commanders with an accepted command in the window (drives PROG-2). The kernel derives both from applied commands, so they are deterministic.

**Who decides an entity is hidden:** the redaction pass uses the coalition visibility predicate at the event's tick (FOW-1). Property test: no public payload references an `EntityId` that fails the predicate.

## 7. Wire messages (server ↔ overlay)
These detail WIRE-PROTOCOL §2. All messages carry `type` and `v` (PROTOCOL_VERSION string). Encoding is msgpack, with JSON in debug mode.

| Message | Fields |
|---|---|
| `Hello` (C→S) | `client_kind: OVERLAY\|PIP\|VERTICAL`, `capability_token: string ≤ 128` (SEC-API-2), `last_tick: Tick\|null` |
| `Welcome` | `server_build: string`, `campaign_id\|null`, `tick_rate_hz: int`, `theater: TheaterStatic` (sent once: nodes with `{node_id, name, kind, pos}`, edges, terrain asset ref) |
| `Snapshot` | `tick`, `entities: EntityView[]`, `nodes: NodeView[]`, `blobs: BlobView[]`, `hud: Hud`, `packages: PackageView[]`, `kill_switch: flags` |
| `Delta` | `tick`, `base_tick`, `upserts: EntityPatch[]`, `removes: EntityId[]`, `node_patches: NodePatch[]`, `blobs: BlobView[]\|null` (null = unchanged; a full replacement on SIGINT refresh), `events: PublicEvent[]` |
| `Hud` (≤ 1 Hz) | `momentum_pct: int 0–100\|null`, `momentum_breakdown: {nodes_held_pct, supply_pct, recent_events: PublicEvent[] ≤ 5, sectors: {sector_id, owner_trend}[]}\|null` (Q-UX-9), `objective_mode: ObjectiveMode`, `objective: {node_id, name, deadline_tick\|null}\|null` (`null` when none is active; `deadline_tick` null in `RELAXED`), `threat_tier`, `campaign_clock: {elapsed_ticks, limit_ticks, paused}`, `ticker: TickerItem[] ≤ 20`, `panels: Panels`, `active_humans: int\|null` (from the latest `PresenceSnapshot`; DI-5: humans only, `null` until the first snapshot), `operators: {by_role: {role, count}[], by_rank_band: {band, count}[]\|null}\|null` (Q-CT-4; `null` until the first snapshot) |
| `Audio` | `sitrep_id`, `text: ModeratedText ≤ 140`, `url: string` (local nginx path), `bus: MUSIC\|FOLEY\|RADIO`, `priority: int 0–9`, `expires_tick` |
| `Control` | `action: RELOAD\|RESYNC\|BANNER\|KILL_SWITCH`, `banner_text: SafeText ≤ 80\|null`, `flags\|null` |
| `Ack` (C→S) | `applied_tick: Tick` |

Field shapes:
- `EntityView`:
  - `{entity_id, unit_kind, side, domain, owner_kind, callsign|null, pos:{x_m:int,y_m:int}, heading_deg:int, speed_mps:int, hp_pct:int 0–100, damage_state: DamageState, fow: TRACK|PAINTED, package_id|null, cosmetic:{halo|null, trail|null}, badges: string[] ≤ 4, probation: bool}`
  - `probation` is true only while the operator has an active conduct restriction (Q-MOD-6); no score is ever sent. Always false for AI entities.
  - `fow` is never SIGINT, because blobs are separate. `callsign` is null for AI entities, which render an `[AI]` label (DI-5).
- `EntityPatch`: `entity_id` plus only the changed fields of `EntityView`.
- `NodeView`: `{node_id, owner: NodeOwner, capture:{side|null, progress_pct:int}, stock_pct:int|null, starvation: OK|LOW|EMPTY|null, hp_pct:int|null}`. `stock_pct`, `starvation` and `hp_pct` are null for ENEMY nodes the coalition can't see (DI-1).
- `BlobView`: `{blob_id: BlobId, cell_center:{x_m,y_m}, size: S|M|L}`.
- `TickerItem`: `{tick, text: ModeratedText ≤ 100, category: CAPTURE|SUPPLY|COMBAT|DIRECTOR|SYSTEM}`.
- `Panels`:
  - `campaign_status: {nodes_held:{coalition,enemy,neutral}, result|null}` (the operator breakdown comes from `Hud.operators`)
  - `tasking_needed: [{job_kind, node_id|null, sector_id|null, slots_open}] ≤ 3` (GAMEPLAY §1b)
  - `top_commanders: {role, rows:[{callsign, value}] ≤ 5}[]`. Real rows only; never padded (DI-4).
  - `active_packages: [{name, lead_callsign|null, member_count}] ≤ 6`
  - `latest_major_event: PublicEvent|null`

## 8. Internal HTTP / admin API
- **Two apps (Q-ARCH-7):** this API backs the private **Command Center** only. The **public site** (replays, leaderboards, stats, later player login) is a separate app with its own read-only API and **no admin routes**; they share contracts and a design system, not an API, so a public-site bug can't reach admin powers.
- **Binding:** served by `nexus.ops` on localhost or the tailnet only, plus the Discord `AdminChannel` (ADMIN-RBAC §7.1). Never exposed publicly; a DAST pass is required before any public exposure (Q-RB-4).
- **Auth:**
  - Every `/admin/*` route requires an authenticated operator session and is authorized per route against the RBAC matrix (ADMIN-RBAC §4). Passkeys (WebAuthn) for owner and admins; Discord OAuth for moderators later, via a verified link (Q-ARCH-12). In P2 there is a single OWNER operator (ADMIN-RBAC §10).
  - Session cookie is `Secure; HttpOnly; SameSite=Strict`, plus a CSRF token on POST (SEC-ID-5 pattern).
  - `/health` and `/metrics` need no auth but are tailnet- or localhost-bound.
- **Responses:** all are JSON, with schemas in `contracts/admin/`.

## 9. Failure modes
| Failure | Behavior |
|---|---|
| Producer emits a payload that fails its schema | The bug is caught in tests. At runtime the producer logs `contract_violation` with the schema id and drops the message (no partial send). Metric + alert. |
| Consumer receives an unknown field or type | Ignore and log (WP-2). Never crash. |
| PROTOCOL_VERSION major mismatch on `Hello` | Server replies `Control{action: RELOAD}`. The overlay shows "UPDATE REQUIRED" (WP-1). |
| Replay log from an older MAJOR | Replay CLI refuses unless a registered migration exists. |
