# tools/

Developer tools: chat simulator (NX-193), replay CLI (NX-032), balance harness (NX-031), load bots. Each tool arrives with its tracker item.

`make check` lints every Python tool here with ruff (`tools/ruff.toml` extends the sim config) and runs `mypy --strict` on the maintained ones (the `TOOLS_TYPED` list in the Makefile); the benchmark spikes `sim-bench/bench.py` and `grid_bench.py` and the `discord-setup` test script are linted but not type-checked.

| Tool | What | Tracker |
|---|---|---|
| [discord-setup](discord-setup/README.md) | Owner-run setup of the community Discord server; never holds a token in a session or repo | NX-354 |
| [sim-determinism](sim-determinism/check.py) | Cross-process determinism check: every golden replay in four interpreters with different `PYTHONHASHSEED` values, against the committed hashes (CI job `sim-determinism`) | NX-105 |
| [sim-bench](sim-bench/bench.py) | Throwaway SIM-CORE benchmark spike: objects vs NumPy, tick p99, frame-stream bytes. Results: [NX-345-BENCH](../docs/review/NX-345-BENCH.md) | NX-345 |
| [sim-bench/grid_bench.py](sim-bench/grid_bench.py) | Benchmark of the real `nexus.core.spatial.UniformGrid`: rebuild + one radius query per entity, tick p50/p95/p99. Results: [NX-104-BENCH](../docs/review/NX-104-BENCH.md) | NX-104 |
| [sim-bench/kernel_bench.py](sim-bench/kernel_bench.py) | Real-kernel scaling bench: the real `step` on a campaign world over an entity ladder (`--ladder 150,300,500,1000,2000 --ticks 3000 --scene convoy\|mixed --seed --settle --profile --out f.json`): ticks/s, step p50/p95/p99/max, board-pass vs plain ticks, largest tick, log-log scaling exponent, top `cProfile` functions. Step only, no frame build (none exists yet). Run from `services/sim`: `uv run --frozen python ../../tools/sim-bench/kernel_bench.py`. Tests: `services/sim/tests/tools/test_kernel_bench.py` | NX-376 |
| [soak](soak/README.md) | Headless soak: one seeded campaign on the real kernel with a `tools/balance` crowd profile for a wall-clock (`--minutes`) or game-time (`--hours`) budget. Records the worst `--worst` single step times (NX-376 spike hunt), RSS slope per game hour (PROPOSED limit `--max-growth-mb-per-h`), `state_hash` checkpoints, then replays the command log and checks every checkpoint. JSON and Markdown report, exit 1 on fail. Nightly CI job `soak`; the weekly 6 h+ run is the PC queue (part 2). Tests: `services/sim/tests/tools/test_soak.py` | NX-033 |
| [replay](replay/replay.py) | Replay CLI (developer only, same commit and image, SC-16): `run`, `verify --expect`, `size` over a snapshot dir and a command log dir (`run`/`verify` load the shipped config for the kernel rules, `--balance --units --weapons --roles --theater --operations` override, and refuse a snapshot with another `config_hash`); `measure.py` runs one game hour of the real runtime with stub handlers and reports storage. Gameplay handlers arrive with their items | NX-032 |
| [balance](balance/README.md) | Balance harness runner, part 1: the real sim stepped headless with scripted viewer personas for the six crowd profiles (`overnight-0` to `surge-500`), a command log per run that replays, and a JSON and Markdown report with the config hash and the A1 to A4 results where measurable (A5, A6 and the rank Gini are not measurable yet). `--profile --seeds --hours --workers --set key=number --theater file --out`. Also reports density (open-job slots per unit, jobs per node), the A2 median and 15-minute tail by persona kind (Q-SIM-97); A7 is measured from P2, not here. Tests: `services/sim/tests/tools` | NX-031 |
| [balance/harness_queue.py](balance/README.md#local-run-queue-nx-381) | Local run queue: open `harness-run` issues from trusted authors are run with the balance harness at a `develop` SHA on the owner's WSL box (hourly timer, `queue-tick.sh`), and the report comes back as an issue comment. Requests may carry `set:` balance overrides (up to `max_overrides`). Config `queue.yaml`; `run-once [--dry-run]`. Tests: `services/sim/tests/tools/test_balance_queue.py` | NX-381 |
